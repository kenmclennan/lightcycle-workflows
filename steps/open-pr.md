# Open-PR

An engine-owned script stage: no agent claims it. `scripts/open-pr.py` runs in the phase's worktree, reads the step with `lc show`, and prints one outcome. A push or `gh` failure exits non-zero, which the engine parks. Delivery is at-least-once, so every step below is safe to repeat. The numbering is cited by other steps; step 6 stays the PR-open and body step.

1. Read the step: the closing note QUOTE is `inputs.previous.report` under a heading naming `inputs.previous.stage`. The branch is the worktree's current branch, and OWNER and REPO come from the `origin` remote. The workspace decides which repo the PR opens in, not the item's `repo`.
2. `git fetch origin`, then sync to the remote head: no remote branch, equal heads, or local commits the remote lacks do nothing; otherwise a clean tree is reset to `origin/BRANCH` and the note names LOCAL and REMOTE, and a dirty tree fails naming both SHAs and the dirty paths.
   - **Size check.** Only when `too-big` is among this stage's declared outcomes, so the spec-phase and no-change instances never measure anything. Before any stack fork, push or `gh stack submit`, and only when the item has a parsed `delivery` entry, measure each layer's whole diff (additions plus deletions from `git diff --numstat`, a binary file counting 0, and so does a generated lockfile, a file whose basename is one of `uv.lock`, `poetry.lock`, `Pipfile.lock`, `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `Cargo.lock`, `Gemfile.lock`, `composer.lock` or `go.sum`): layer 1 against BASE_REF, layer n against layer n-1, or `BASE_REF...HEAD` for one PR. A file for which `git check-attr linguist-generated -- <path>` reports `set` or `true` in the checked-out branch counts 0, as a listed lockfile does. The limit is the config key `layer-lines-limit`, read from `LC_WORKFLOW_CONFIG_LAYER_LINES_LIMIT`, with no default, and a value that is unset, blank or not a positive integer fails the stage naming the key. A layer over the limit whose `Layer n` line lacks the word `irreducible` (for one PR, whose `Reasons` line lacks it) is not pushed: print `too-big` with a note of the form `Re-cut: layer 2 of 3 is 1172 lines, over layer-lines-limit 400 and not marked irreducible`, naming every such layer. The check reads git state only, so it is safe to repeat. A layer the run's recorded stack shows as merged on GitHub is left out before measuring, so the first unmerged layer is measured against BASE_REF, and with fewer than two unmerged layers left the one PR is measured against BASE_REF; a layer keeps its original `Layer <n>` number when its `irreducible` marker is read. A refusal whose note equals the `report` of this stage's previous `too-big` step, found by following `previous_step`, is not printed as `too-big`: the stage fails naming both figures, so the engine parks it for a human, with the same figure never re-cut a third time.
   - **Layer check.** Only when `layer-red` is among this stage's declared outcomes and the stack path is taken, so a single PR and the spec-phase and no-change instances never run it. The command is the one line in `.lightcycle/layer-check`, read from BASE_REF (`git show "${BASE_REF}:.lightcycle/layer-check"`), never from the layer, and run with `sh -c`; a missing or blank file skips with the note `layer check skipped: no .lightcycle/layer-check at <BASE_REF>`. The contract a repo adopts: a fast static check, typecheck and lint only, never the test suite (the full suites stay in CI), that owns its own setup and is safe to run concurrently in separate directories. After `gh stack rebase` and before any push, each unmerged layer gets a fresh detached worktree at its head and the command runs in all of them at once, each in its own process group, limited by the config key `layer-check-timeout-seconds` (`LC_WORKFLOW_CONFIG_LAYER_CHECK_TIMEOUT_SECONDS`, a positive integer no greater than 240, failing the stage naming the key otherwise, the ceiling keeping the whole check inside the engine's `script-timeout-seconds`). A non-zero exit or a timeout is red; a timeout is never a pass. The stage prints `layer-red` naming the lowest red layer by position, `Layer <n> of <m> (<branch> at <short sha>) failed the layer check: exit <code> after <s> s` or `... layer check timed out after <limit> s`, then the command and the last 40 lines of output (at most 4000 characters), and pushes nothing. On success the `done` note carries each layer's time, `layer check: layer 1 of 3 passed in 38 s; ...`. A `layer-red` whose `Layer <n> of <m> (<branch> at <short sha>)` prefix equals the previous `layer-red` step's of this stage, found by following `previous_step`, fails the stage with `Layer check loop: ...` so the engine parks it for a human. The worktrees are removed afterwards and the item's branch is untouched.
   - **Stack fork.** If the worktree holds a stack (`gh stack view --json` lists two or more branches, the last being BRANCH), steps 3 to 6 are replaced: `gh stack rebase` in place of step 4's rebase, with a conflict aborted and printed as `conflicted`; then, when the run already records a `stack` and the stack on GitHub (read through `gh api`) has a different branch set from the local layers, a re-cut: `gh stack unstack <n>` and `gh stack init <local layers bottom to top>` first, then `gh stack submit --auto --open`, then close each PR whose head is no longer a layer with the comment `Layer dropped by a re-cut; see <top PR url>`, delete its branch, and attach the new stack and top PR with `--replace`; a dissolved or unchanged stack skips that and submits as normal. The submit pushes and opens a PR per layer; then `lc attach ITEM stack STACK_URL` and `lc attach ITEM pr TOP_URL`. Each layer's PR body is the item marker, then between the sync markers that layer's tip commit message and a `## Delivery` section quoting its `Layer <n>` line from the item's `delivery` entry; the top layer's body also carries the `Decision` and `Reasons` lines and the QUOTE. Titles are each layer's tip commit subject. Exit code 9 from `gh stack` (stacks not enabled for the repo) falls back to one PR from BRANCH with steps 3 to 6 as written, its body noting that stacks are not enabled and carrying the `delivery` reasons, and no `stack` attached; any other non-zero exit fails the stage. Steps 7 and 8 then follow. Layers the recorded stack shows as merged are dropped from the local layers first, so a stack whose lower layers have merged is never re-cut or rebased with them. A worktree with no stack never takes this fork. Before `gh stack rebase`, each local layer other than BRANCH that has an `origin/<layer>` is moved to that remote head when it is behind it or holds only commits the remote has or once held and has since rewritten; a layer with a commit the remote never held, or one checked out in another worktree, is left alone, and the note names every layer moved or held back.
3. Look up an open PR for the branch. If one exists, `git push --force-with-lease`, then resync the text between the `<!-- lc:body -->` and `<!-- /lc:body -->` markers from the commit message and QUOTE, add the `<!-- lc:item=ITEM -->` marker if absent, leave everything outside the markers and a body without markers alone, resync the title to the commit subject, and continue at step 7. If none exists but the phase run already records a `pr`, fail naming the divergence. Otherwise continue.
4. Resolve BASE_REF: `git remote set-head origin --auto`, then `git symbolic-ref --short refs/remotes/origin/HEAD`, which prints `origin/<the repo's default branch>`; a failure to resolve it fails the stage naming git's output and never falls back to a literal branch name. Then `git rebase BASE_REF`. On conflict, abort the rebase and print `conflicted` when the stage declares that outcome, otherwise fail naming the conflicting paths.
5. `git push --force-with-lease`. A failure exits non-zero with git's message.
6. Find or open the PR, never a duplicate: look up again, and only if none exists create one against the repo's default branch (BASE_REF without its `origin/` prefix) titled with the commit subject exactly. The body is the item marker on its own first line, then the commit message and, when there is a QUOTE, a `## Closing note from <stage>` heading and QUOTE exactly as written, all between the sync markers. If the create call errors, look up again before failing. Then `lc attach ITEM pr URL`; re-attaching the same url on a rework pass is idempotent.
7. Close the loop on queued rework. For each lc acknowledgement carrying `<!-- lc:decision=rework -->` with no reply carrying its `<!-- lc:completes=ID -->` marker and created before the commit time, post one completion reply in its thread. The reply names the pushed SHA and the commit subject and says it does not verify the push addresses the request.
8. Print `{"outcome": "done", "note": ...}`.
