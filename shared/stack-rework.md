**Stack rework.** When the item's `delivery` entry reads `Decision: stack`, a push over the stack follows this and nothing else. After `git fetch origin`, record `SHA=$(git rev-parse origin/<layer-branch>)` for every layer before changing anything. Check out the layer a finding names, commit the fix there, then cascade the layers above with `gh stack rebase`: resolve each conflict, continue with `--continue`, and run the repo's own tests. Push each rewritten layer, bottom to top, with `git push --force-with-lease=<layer-branch>:<SHA>`, keeping any commits others pushed in the rebased history. A refused push means someone pushed in between: stop, push nothing further, and end the step by its own rule for a refused lease (never park for it). Never use `gh stack push` or `gh stack sync`: they force-push without a lease.
