**Criteria for one PR or a stack.** These criteria are stated here in this step, not in a guidance entry. A layer, or the one PR when the branch is not cut, is one self-contained change that does one thing, with its own tests, and the system works once it lands. A refactor goes in its own change, never folded into a feature. Too small is also wrong: a layer a reviewer cannot judge without the next one is not a layer. Aim for about 100 lines of diff. Five rules sharpen that:

- **Cut at first use.** A coherent thing over the limit is cut where it is first used: the contract (a type, a schema, a library function) ships with the first command, screen or caller that uses it, and each further group that uses it is its own layer. A layer whose only consumer is the next layer is not a layer.
- **Depend on the lowest layer that provides what you need.** A layer built on the one before it by default is rewritten by every merge below it, so place each layer's content with the lowest layer it needs in mind.
- **One layer appends to a list-shaped file.** Two layers in one stack never both append to the same list-shaped file (a glossary, a README, a design doc): those edits go in the layer that ships the behaviour, or in the top layer only.
- **Change a shared contract and its readers together.** A layer that changes a shared contract (a schema, a record version, a type, a library function's signature) carries every reader of it, in code and tests, so each layer passes its own CI alone. A reader left to a higher layer is a red layer below a green top PR.
- **Stay under the limit.** The config key `layer-lines-limit` (read it from the claim's `workflow_config`) is the most diff lines (additions plus deletions, the whole diff: code, tests, fixtures, schema examples and docs) one layer, or the one PR, may carry. `open-pr` measures it and refuses a layer over it, sending the work back here as a `Re-cut:` line. The only exemption is a layer that cannot be divided without breaking it: the cutter writes `irreducible` and the reason in that layer's `Layer` line, or in the `Reasons` line for one PR, and the reviewer accepts it only if the reason holds.
